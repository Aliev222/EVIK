# Авро — Модель дохода (решение)

> Как платформа зарабатывает и как защищён доход от утечки на наличных.
> Решение владельца (Расул), зафиксировано август 2026.

## Решение

**Основная модель — комиссия 15% с enforce долга. Подписка — опция (0% комиссии).**

- Карта: комиссия 15% собирается автоматически (деньги идут через платформу).
- Наличные: водитель забирает все деньги, платформе пишется **долг 15%** на кошелёк.
- Долг **enforce'ится**: при превышении порога водитель не может брать новые заказы, пока не погасит.
- Погашение долга: автоматически с карточных заработков ИЛИ вручную через **СБП** (QR/по номеру из банка водителя — без ввода карты в приложение).
- Подписка (день/неделя/месяц) — альтернатива: активна → комиссия 0%, водитель оставляет 100%. Для тех, кто много ездит.

### Почему так
- Комиссия масштабируется с оборотом лучше фикс-подписки (upside по доходу).
- Но на наличных комиссия собираема ТОЛЬКО при enforce долга — иначе цифра на бумаге, а не в кассе.
- СБП решает вопрос «нет карты у водителя»: платит из своего банка по QR. У зарегистрированного (самозанятый/ИП) водителя банковский счёт есть всегда.

## Что уже есть в коде (проверено)
- Комиссия 15% из `platform_settings`, при активной подписке → 0% (`finance.go` CompleteOrderFinancially, `effectivePercent=0`).
- Наличные: `debt_balance += commission`, транзакция `cash_commission_debt` (payment_repository.go ~601-616).
- Карта: сначала гасит долг из заработка (`debt_repayment`), остаток → pending с холдом (~617-647).
- Наличные завершаются при финализации водителем (недавний фикс), долг пишется сразу.
- Подписка: планы pro_day/week/month, `hasActiveSubscriptionTx`, умное продление (в контексте).

## Чего НЕ хватает (дыра)
- `EnsureCanWork` (gate.go) проверяет документы + налоги + подписку, но **НЕ проверяет долг** → водитель копит долг бесконечно и продолжает работать. Долг не enforce'ится.
- Нет экрана/механизма погашения долга.
- Подписка не обязательна (флаг `subscriptionRequired` не включён как основной путь — и не нужен, раз модель комиссионная).

## Что делать

### Сейчас (без эквайринга/ИП — готовим логику)
1. **Порог долга** в конфиг/настройки (напр. `max_cash_debt_kopecks`, значение задать — например 100000 = 1000₽).
2. **Enforce в `EnsureCanWork`**: если `debt_balance > порог` → запретить работу (новая ошибка `ErrOutstandingDebtBlocksWork`), водитель не выходит на линию / не принимает заказы. Тесты на все ветки.
3. **Экран «Погасить долг»** во фронте водителя: показывает сумму долга, как погасить (СБП — плейсхолдер до Cyclops; «или отработайте картой»). Появляется, когда долг близок/превысил порог.
4. **Не блокировать вывод** уже заработанного из-за долга (payout-гейт уже не зависит от долга — сохранить).

### Позже (с ИП + эквайрингом/Cyclops)
5. **Погашение долга через СБП**: генерация QR (Cyclops `generate_sbp_qrcode`), зачёт оплаты → `debt_balance -= сумма`, транзакция погашения. Вебхук подтверждает.
6. **Эквайринг для покупки подписки** (карта) — подписка как опция 0%.
7. **Экран покупки подписки** + тумблер подписка/комиссия (задача #6 частично).
8. Опционально: бесплатный триал подписки новым водителям.

## Пример (enforce долга)
Порог 1000₽. Водитель возит по налу: долг 150 → 300 → … → 1000₽ → блок «Погасите 1000₽».
Платит по СБП из своего банка ИЛИ делает карточные заказы (гасят долг автоматически) → долг 0 → снова онлайн.
Итог: 15% собираются пачкой, наличные больше не протекают.

## Edge-кейсы / честные оговорки
- «Переведи мне на карту по телефону, не заказывай в приложении» — увод заказа мимо платформы вообще; ни одна модель не спасёт на 100%, лечится ценностью приложения (диспетчеризация, поток, рейтинги). Если заказ идёт через приложение — долг капнет.
- Смена способа оплаты на наличные перестаёт быть лазейкой: долг всё равно накопится и заблокирует. → смену оплаты можно разрешить (задача #5), она больше не угроза доходу.
- Подписка активна → комиссия 0% → долг не пишется (уже в коде). Подписчики вне enforce-механики.

## Связанные задачи
- Enforce долга (сейчас) — новая задача.
- Смена способа оплаты (#5) — после решения по модели: разрешить, т.к. не угроза.
- СБП-погашение + подписка + эквайринг — Фаза 4 (с ИП).
- Апселл подписки (#6).
