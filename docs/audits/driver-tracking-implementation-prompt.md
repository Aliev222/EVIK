## 2. Пользовательский путь

- [ ] Проследить принятие заказа, восстановление активного заказа, deep link и повторное открытие приложения. Каждый путь должен запускать одну корректную tracking session.
- [ ] Устранить разрыв DriverInfoScreen/TrackingScreen: один экран сопровождения либо общая сессия и общие компоненты без дублирующих подписок и расчётов.
- [ ] Сразу после назначения показывать известную позицию водителя с её возрастом; при отсутствии свежей позиции писать «Уточняем местоположение эвакуатора».
- [ ] Оставить доступными сведения о водителе, эвакуаторе, госномере, адресах и разрешённых действиях. Основные действия — связь с водителем и управление просмотром карты.
- [ ] «Позвонить» действительно открывает звонок; «Чат» использовать только для настоящего чата. Для sms: написать «Сообщение/SMS». При отсутствии номера отключать действие с объяснением, не оставлять активную пустую кнопку.
- [ ] Переход назад и раскрытие деталей не должны сбрасывать заказ, закрывать нужную подписку или повторно открывать WebSocket.

## 3. Композиция и стиль frontend

- [ ] Сохранить визуальный язык EVIK: светлый фон, существующие шрифты, аккуратный оранжевый акцент. Не создавать декоративную панель вместо рабочей карты.
- [ ] Верхняя плашка: статус и главное время человеческим языком. Убрать «ETA:»; использовать «Будет примерно через 8 мин», «Эвакуатор прибыл», «Идёт погрузка», «Везём автомобиль» по реальному этапу.
- [ ] Нижняя панель компактная и раскрываемая: в свёрнутом состоянии водитель, эвакуатор, номер, связь; адреса и детали раскрываются без перехода на отдельный экран.
- [ ] Карта остаётся главным содержимым. Рассчитывать полезную область по реальным размерам верхней/нижней панелей, safe area и положению sheet, без magic offsets 330/238.
- [ ] Не дублировать «К заказу» двумя кнопками; сделать понятную иерархию действий. Не выводить технические ID, raw speed, seq, routeVersion, диагностические сообщения.
- [ ] Не использовать мелкий 11 px текст для главной информации. Проверить длинные ФИО, номер/модель, адреса; исключить overflow от жёстких высот 68/70.
- [ ] Проверить ширины 320/360/390/430 logical pixels и системный текст 100/130/160/200%. Панель должна прокручиваться/раскрываться, сохраняя доступ к основным действиям.
- [ ] Добавить понятные semantics/labels, не зависеть только от цвета, обеспечить различимость текста и удобные области нажатия. Проверить экранным диктором.

## 4. Карта, маркер и камера

- [ ] Устранить наблюдавшуюся надпись «API KEY REQUIRED» на подложке: проверить фактический tile URL, условия/авторизацию провайдера и конфигурацию сборки. Не маскировать проблему заглушкой с якобы рабочей картой.
- [ ] Показывать attribution выбранного провайдера в видимой области, не под нижней карточкой. Ошибка подложки не должна удалять данные заказа или создавать впечатление потери заказа.
- [ ] Различить эвакуатор, погрузку A, назначение B и личную геопозицию клиента; исключить движение машины в позицию телефона клиента.
- [ ] На дальнем масштабе маркеры не перекрывают эвакуатор: приоритет и видимость A/B зависят от активного этапа, учитываются коллизии.
- [ ] Использовать читаемый силуэт эвакуатора сверху, ориентированный носом по bearing. Не использовать большую карточную иллюстрацию или вращающийся боковой грузовик.
- [ ] Плавно ограничить размер маркера по zoom. Стартовая настройка — 28–44 logical pixels на zoom 12–18 с clamp вне диапазона; скорректировать после визуального сравнения. Не масштабировать экспоненциально и не путать logical/physical pixels.
- [ ] Проверить поворот карты: направление машины относительно дороги корректно, rotation учитывается ровно один раз; курс 359°→1° не вызывает полный оборот.
- [ ] Анимировать из текущего отображаемого положения, по подтверждённой геометрии маршрута при достаточной уверенности. Не срезать повороты и не притягивать эвакуатор во дворе к соседней дороге.
- [ ] Исключить дрожание курса на стоянке. При разрыве GPS/связи остановить прогноз, показать последнюю точку и её возраст.
- [ ] Отделить слой анимации от rebuild всего экрана и повторного camera fit на каждом кадре.
- [ ] Реализовать режимы «обзор активного участка», «следование», «ручной просмотр». Для подачи fit охватывает эвакуатор и погрузку, для перевозки — эвакуатор и назначение.
- [ ] Pinch, drag, rotate, +/− переключают в ручной просмотр. Новые координаты, маршрут и карточки не сбивают выбранную камеру. Явная кнопка возвращает к эвакуатору/маршруту.
- [ ] Исправить воспроизведённое исчезновение кнопки возврата после её нажатия: она вновь доступна при ручном изменении камеры, независимо от прихода следующего маршрута.
- [ ] «Моя геопозиция» и «Показать эвакуатор» имеют разные понятные функции. Кнопки не перекрывают маршрутные точки и не прячутся за sheet.
- [ ] Линия контрастная и аккуратная; пройденный участок сокращается/приглушается, оставшийся выделяется. Не выдавать отрезок from→to за дорожный маршрут при пустой геометрии.

## 5. Этапы и состояния

- [ ] Отдельно отрисовать: принят/подача, прибыл, погрузка, перевозка, ожидание оплаты, завершение и отмена. Сначала проверить, какие этапы реально различает backend; не выдумывать отсутствующую фазу на клиенте.
- [ ] Заголовок, прогресс, маршрутная цель, ETA и доступные действия согласованы с одной моделью состояния. Не держать постоянный текст «едет к вам» для всех этапов.
- [ ] Прогресс не должен возвращаться к «Принят» для отсутствующего в списке статуса; текущий этап визуально отличается от уже завершённого.
- [ ] Предусмотреть: загрузка, нет первой позиции, координаты задерживаются, нет GPS, offline, reconnect, перестроение, маршрут недоступен, водительские данные неполны, ошибка карты.
- [ ] Сохранять последнюю подтверждённую геометрию при временной ошибке с честной пометкой; не мигать пустой картой. «Перестраиваем маршрут» показывать без блокировки карты.
- [ ] ETA приблизительное и получено по дороге. Истечение расчётного времени не означает фактическое прибытие. Нет свежих данных — «Время уточняется».

## 6. Телеметрия и соединение

- [ ] Исправить 50-метровый фильтр: не блокировать клиентские события экономией записей GEO. Разделить время принятия GPS, публикации и сохранения; смену заказа/фазы передавать независимо от расстояния.
- [ ] Нормализовать toDestination/to_destination и остальные значения; HTTP heartbeat не сбрасывает фазу, bearing и speed из-за отсутствующих полей.
- [ ] Единый контракт WS/HTTP: идентификаторы сессии/заказа/водителя, sampledAt, receivedAt, seq, accuracyM, nullable bearing/speed с явными единицами. Повтор старой точки не обновляет sampledAt.
- [ ] Фильтровать неверный заказ/водителя, дубликаты, устаревшие события и неправдоподобные GPS-выбросы. Сохранять достоверное измерение, не подменять его фиктивно свежим.
- [ ] Один владелец WebSocket: ожидание ready, закрытие предыдущего соединения, backoff/jitter, auth refresh, проверка heartbeat/pong; без двойных reconnect-таймеров.
- [ ] Initial snapshot и resync на reconnect/resume/restart согласованы со stream через sequence/watermark. После потери события состояние восстанавливается.
- [ ] Завершение/отмена закрывают клиентский live-доступ и очищают сессию; следующий заказ не наследует старые координаты и маршруты. Nullable copyWith действительно очищает значения.
- [ ] Проверить background location на iOS/Android, блокировку экрана и переключение во внешний навигатор. Dart timer сам по себе не является гарантией работы в фоне.

## 7. Общий маршрут и перестроение

- [ ] Одна каноническая routeVersion/geometry/phase/target для обоих клиентов; убрать независимые неиспользуемые preview-запросы.
- [ ] Сначала обеспечить route parity внутри EVIK. Для полного совпадения с водительским ведением использовать встроенную навигацию/поддерживаемую интеграцию, которая принимает или возвращает выбранный маршрут.
- [ ] Не обещать совпадение с внешним Яндекс/2ГИС/Google, если интеграция передаёт только адрес. Если внешнее приложение сохраняется, обозначить линию как расчётный маршрут EVIK и явно зафиксировать эту незакрытую часть требования.
- [ ] Съезд определять относительно подходящего сегмента дороги с учётом accuracy, heading и нескольких последовательных точек; не перестраивать по одному GPS-выбросу.
- [ ] При смене этапа/адреса/выбранной альтернативы обновлять маршрут сразу. Один актуальный запрос, generation/version guards; старый ответ не заменяет новый.
- [ ] Учитывать пустой/гружёный эвакуатор, размеры и массу там, где routing provider поддерживает ограничения. Обычный car profile не объявлять грузовой навигацией.
- [ ] Проверить production routing host и покрытие региона. Не основывать надёжность платного сервиса на непроверенном demo endpoint.
